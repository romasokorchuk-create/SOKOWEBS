# Адмінка SOKO — як увімкнути

Адмінка: `https://ТВІЙ-САЙТ/admin/`. Вхід — пошта + пароль + код 2FA з телефона.
Пароль зберігається лише в Supabase (у хешованому вигляді), у коді сайту його немає.

## 1. Проєкт Supabase (≈5 хв)
1. Зареєструйся на https://supabase.com → **New project** (регіон Frankfurt, пароль бази збережи собі й нікому не давай).
2. **SQL Editor → New query** → встав увесь файл `schema.sql` → **Run**. Має бути «Success».

## 2. Твій акаунт адміна
1. **Authentication → Sign In / Providers → Email**: вимкни **Allow new users to sign up** (щоб ніхто інший не зареєструвався).
2. **Authentication → Users → Add user → Create new user**: твоя пошта + довгий пароль (12+ символів), галочка **Auto Confirm User**.
3. **SQL Editor**, заміни пошту й виконай:
   ```sql
   insert into public.admins (user_id) select id from auth.users where email = 'ТВОЯ@ПОШТА';
   ```

## 3. Безпека входу
- **Authentication → Multi-Factor**: TOTP увімкнено (так за замовчуванням). Код 2FA адмінка попросить налаштувати при першому вході — без нього дані не відкриються.
- **Authentication → Sign In / Providers → Email → Password**: мінімальна довжина **12**, вимоги — малі й великі літери, цифри, символи.
- (Pro-тариф) **Leaked password protection** — перевірка пароля в базах витоків на сервері. Адмінка й так робить це в браузері.

## 4. Лист для зміни пароля
**Authentication → URL Configuration**:
- **Site URL**: `https://ТВІЙ-САЙТ/`
- **Redirect URLs** → Add: `https://ТВІЙ-САЙТ/admin/`

Без цього посилання з листа не відкриє адмінку. Змінити пароль: на сторінці входу «Забули пароль?» або в адмінці → **Безпека**. Після посилання з листа адмінка все одно попросить код 2FA — тож доступу лише до пошти нападнику мало.

## 5. Підключити сайт
**Project Settings → API Keys** → скопіюй **Project URL** і **anon / publishable** key у `config.js` (у корені репозиторію):
```js
window.SOKO_CONFIG = { supabaseUrl: 'https://xxxx.supabase.co', supabaseAnonKey: 'ключ' };
```
Цей ключ публічний за призначенням — захист тримають правила RLS у базі.
**Ніколи** не вставляй **service_role / secret** key: він обходить усі правила (адмінка з ним навіть не запуститься).

## Що перевірено
Схему атаковано в справжньому Postgres від імені відвідувача, чужого акаунта, адміна без 2FA і адміна з 2FA — див. звіт у чаті.
